# Conversation Upgrades — Design (Open-Mic + Faster Responses + Brain Greeting)

**Date:** 2026-06-02
**Goal:** Make talking to Friday feel like a real, fast, continuous conversation:
always-listening open mic (no tap-to-talk), lower response latency, and a greeting
that's generated by the brain and remembered as part of the conversation.

Three related but separable upgrades, built in one effort.

## Decisions locked (from brainstorming)

- **Listening model:** Open mic — mic opens on load and stays open; Friday responds to
  speech without a wake word. Guards required: client VAD (don't send silence) and
  pause-listening-while-speaking (don't reply to her own voice).
- **Self-hearing:** Pause listening while Friday is in `speaking` state; resume on idle.
  (Voice barge-in during her turn is therefore OFF; typing still interrupts.)
- **Mute control:** The existing mic button becomes a mute/unmute toggle (open-mic on by
  default).
- **Latency:** Keep `nemotron-3-super:cloud`; optimize the pipeline only (no model/quality
  change).
- **Greeting:** Brain-generated each boot (time/identity/last-seen aware), recorded as
  Friday's first assistant turn in episodic memory. Graceful fallback to the templated
  line if the brain is unreachable.

## Context (verified 2026-06-02)

- `ui/js/app.js`: `startRecording()` opens the mic on the mic-button toggle, chunks audio
  every 3s (stop/start MediaRecorder) and sends every chunk unconditionally; `startMicVAD`
  already computes mic RMS (used for barge-in). `stopSpeaking()` handles barge-in.
  `setState()` tracks idle/listening/thinking/speaking/acting on `document.body`.
- `core/voice_session.py`: `run_turn` buffers a held sentence and only dispatches the
  previous one (hold-one-ahead); TTS is awaited per segment (serial). `summarize_result`,
  approval/result markers handled.
- `core/main.py`: `broadcast_proactive_message` uses the v2 contract; `GET /api/greeting`
  returns a templated line (not recorded in memory, not via brain); `{type:speak}` control
  speaks verbatim.
- `core/brain.py`: `get_streaming_response` builds system prompt from persona + skills +
  full episodic + memory context + exemplars each call.
- `python3` + `PYTHONPATH=.`; async tests via `asyncio.run()`.

## Upgrade 1 — Always-listening open mic (UI: `ui/js/app.js`)

- **Auto-start:** open the mic after boot/permission instead of requiring the toggle.
- **Client VAD gating:** only stream audio chunks when recent mic RMS indicates speech
  (above a threshold for the chunk window); skip silence/quiet noise. Reuse the existing
  analyser. A small pure helper `shouldSendChunk(rmsSamples, threshold)` is unit-testable
  (ported to a tiny JS-agnostic truth table mirrored in Python if needed; otherwise covered
  by manual verification — the decision rule is trivial).
- **Pause-while-speaking:** gate sending on `document.body.dataset.state !== 'speaking'`
  (and not muted). When Friday speaks, suppress mic sends; resume at idle.
- **Mic button = mute toggle:** `muted` state; when muted, never send audio and show the
  button active-muted. Default unmuted (listening).
- **Barge-in:** with pause-while-speaking, voice barge-in during her turn is disabled by
  design; the existing `interrupt` path remains for typed interruption / future use.

## Upgrade 2 — Faster responses (backend pipeline, no model change)

- **Earlier first audio:** in `voice_session.run_turn`, dispatch the first completed
  sentence segment to TTS immediately rather than holding it one-ahead. Keep pipelining for
  subsequent segments.
- **Pipelined TTS:** synthesize the next segment while the current one's audio is in flight
  (overlap TTS generation with sending), removing inter-sentence gaps. Implemented by
  launching the next `generate_speech_timed` as a task while emitting the current.
- **Leaner prompt/context:** in `brain.get_streaming_response`, cap the episodic history and
  exemplars included per call (e.g. last N turns, ≤3 exemplars) and avoid duplicate text, to
  reduce input tokens → faster first token. A pure helper `trim_history(messages, max_turns)`
  is unit-tested.
- No change to model, temperature, or persona content.

## Upgrade 3 — Brain-generated greeting in memory (backend)

- `GET /api/greeting` (or a new path) asks the brain to generate a short in-persona greeting
  using bio + time-of-day + last-seen, then records it as an assistant episodic turn so
  Friday is aware she greeted the user. Returns `{text}`.
- A pure helper `greeting_prompt(bio, hour, minutes_since_seen) -> str` builds the LLM
  instruction (unit-tested); the LLM call and memory write live in the endpoint.
- Fallback: if the brain call fails, use the existing templated `build_greeting` and still
  record it. Boot never hangs.
- The UI continues to speak the returned text via the `{type:speak}` control.

## Data flow

- Talk → (VAD + not-speaking + not-muted) → chunk sent → STT → `run_turn` (leaner prompt,
  earlier+pipelined TTS) → captions/transcript/orb → on `speaking` the client pauses sending
  → on `idle` it resumes.
- Boot → brain greeting generated + recorded → spoken via `speak`.

## Error handling

- Mic permission denied → no sends; mute button reflects unavailable; app still works by text.
- VAD false negatives (misses quiet speech) → user can speak slightly louder or type; tuned
  conservatively to avoid sending the room.
- TTS pipeline task failure → fall back to serial synth for that segment (existing per-segment
  try/except already degrades to a caption without audio).
- Greeting brain failure → templated fallback, still recorded.

## Testing

- Backend (pytest): `trim_history` (caps turns, preserves order/roles), `greeting_prompt`
  (includes time-of-day + name/absence cues), and a `run_turn` ordering test that the FIRST
  caption is emitted before the full reply completes (using the existing fake brain/tts).
- UI: verified in-browser — mic auto-starts, silence isn't sent, Friday doesn't reply to
  herself, mute toggle works, replies start speaking noticeably sooner.

## Out of scope

Model swap (kept nemotron); server-side acoustic echo cancellation; wake-word UI mode
(backend wake-word logic stays but UI runs open-mic); streaming token-level TTS (we stay at
sentence granularity).

## Success criteria

- Mic is always on (no tap-to-talk); silence and Friday's own voice don't trigger replies;
  mic button mutes/unmutes.
- First audio of a reply starts sooner; no gaps between sentences.
- Boot greeting is brain-generated, spoken, and present in episodic memory as Friday's turn.
- New pure helpers unit-tested; full app verified in-browser.
